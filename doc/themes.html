Themes

Themes are a way to gather together the properties that control the appearance of the editor.

The distribution comes with a themes directory which contains several themes. You can specify the theme to use by setting the theme property in your preferences file: 

    theme=Anokha
The specified theme file is loaded as an additional preferences file after ~/.config/j/prefs is loaded.

You can use the themePath property to specify a list of directories that will be searched (in the specified order) for theme files when the full path of the theme file is not given. For example: 

    themePath=/home/peter:/home/peter/j/themes:/usr/local/share/j/themes

Two of the bundled themes, AnokhaClassic.lisp and Kodiak.lisp, are Lisp rather than preference files. They are not loaded by the theme property above; you load them from your init.lisp, which means they need the abcl extension. Without it they do nothing at all — no error, no theme.

Styles

A style. property may be a number, the sum of 1 for bold, 2 for italic, 4 for underline and 8 for strikethrough (0 is plain, 3 bold italic), or words: any of plain, bold, italic, underline and strikethrough. 

    style.heading = bold italic
    MarkdownMode.style.cancelled = strikethrough

Shared styles and links

Some styles are shared by every mode that has a use for them: heading, link, url, code, emphasis, strong, quote, muted, listMarker, todo, inProgress, inProgressMarker, done and cancelled. Without a theme's say they have colors made for a light background and others for a dark one, chosen by color.background.

A mode's own things link to the shared ones, the way emacs faces inherit and nvim links highlight groups, so a theme sets color.heading once and every mode's headings follow. A thing takes from its link whatever its own color. and style. properties leave out. A theme or your preferences can link a thing elsewhere, for all modes or for one: 

    link.url = comment
    MarkdownMode.link.heading1 = keyword

listStyles shows what each style came to and where from. In a theme or preferences file, every line that sets a color shows a swatch of it in the gutter. The theme in use, and a file with no extension on themePath or in j's own themes directory, are edited as properties files even without a -*- Mode: Properties -*- first line; so is one in another directory named themes if its first setting is a color., style. or link. one.
