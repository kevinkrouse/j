Extending J

An extension is a jar that j discovers at startup and that adds commands, key bindings, editor hooks, or a connection to a language runtime. Lisp support is itself an extension: init.lisp, M-x jlisp and evaluating a form in the location bar all come from the abcl extension, which ships with j but can be removed.

Where extensions live

j looks in two places, in this order: 

    <install directory>/lib/extensions/<name>/
    ~/.config/j/extensions/<name>/
The first is where the extensions bundled with j are installed; the second is yours. See Where J Keeps Its Files for how the configuration directory is chosen.

Each extension gets a directory of its own, holding its jar and any libraries it depends on. Every jar in that directory is loaded together, in a class loader of its own — so two extensions can depend on different versions of the same library without colliding.

Turning extensions off

To skip one extension, name it in your preferences file: 

    disabledExtensions = abcl
The value is a comma-separated list of extension names.

To skip all of them for one run, start j with --no-extensions. That is the way back in if an extension is keeping the editor from starting.

Creating an extension

An extension implements org.armedbear.j.extension.Extension and declares itself the way any java.util.ServiceLoader service does, in a file named 

    META-INF/services/org.armedbear.j.extension.Extension
containing the fully qualified name of your class. There is no manifest format of j's own to learn. 
    package com.example.j;

    import org.armedbear.j.extension.Extension;
    import org.armedbear.j.extension.ExtensionContext;

    public final class HelloExtension implements Extension
    {
        public String getName()    { return "hello"; }
        public String getVersion() { return "1.0"; }

        public void initialize(ExtensionContext context)
        {
            context.registerCommand("hello", HelloCommands.class, "hello");
        }
    }

getName is what disabledExtensions matches on, so keep it short, lower-case and stable.

initialize should execute quickly and only register things. For example, the abcl extension registers a command and three providers at startup and does not boot an interpreter until something evaluates a form.

If initialize throws, the failure is logged and j carries on without that extension. One broken jar must not stop the editor from starting.

What you can register

Method Adds
registerCommand(name, owner, method) A command, callable with M-x name or from a key binding. The method must be public static, taking either no arguments or a single String.
registerHooks(EditorHooks) Notifications: a buffer was activated, a file opened, a buffer saved, a mode created, an event handled.
registerKeyMapProvider(KeyMapProvider) The global key map, or the key map for a mode. Return null to leave it to j.
registerLanguageClient(LanguageClient) A connection to a language runtime, so that evaluating a form in the location bar, in a compilation buffer or from init.lisp reaches it.

Note that registerCommand takes a Class, not a class name. j resolves the names of its own commands reflectively, on its own class loader, which cannot see anything in the extension — so you hand it a class your loader has already resolved.

A function as a command

A key can be bound to something other than a named command: a closure defined in whatever language your extension speaks. Wrap it in an org.armedbear.j.extension.ScriptFunction, which j invokes without knowing what it is, and asks to describe itself for M-x describeKey.

Preferences

Read and write your own settings with ExtensionContext.getPreferences(). Prefix your keys with your extension's name; j's own Property table is closed.

Building one

In j's own source tree, an extension is a directory under extensions/ with a deps.edn of its own naming its dependencies, and a src/ beside it. bb extensions compiles and packages every one of them into build/lib/extensions/, and bb test-extensions runs their tests. Look at extensions/abcl/ for a worked example.

The old mechanism

Earlier releases had an extension= preference naming a single class with a run() method, loaded from the configuration directory.
