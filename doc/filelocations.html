Where J Keeps Its Files

J follows the XDG Base Directory Specification. What older versions of j kept together in ~/.j is split across four directories, according to how much you would mind losing it:

Directory Default Contents
$XDG_CONFIG_HOME/j ~/.config/j Things you edit by hand: prefs, aliases, init.lisp, and extensions/, which holds your own extensions, one directory each
$XDG_DATA_HOME/j ~/.local/share/j Things you would miss: mail, registers, addresses, news
$XDG_STATE_HOME/j ~/.local/state/j Things j maintains for you: sessions, window placement, the recent file list, file history, autosave and recovery files, the log
$XDG_CACHE_HOME/j ~/.cache/j Things j can rebuild: the file cache, tag files, temporary files
$XDG_RUNTIME_DIR/j the state directory Things belonging to the running instance: the server port file, the swank port file

The environment variables above are honoured on every platform. Where one is not set, j falls back on whatever is normal for the platform: %APPDATA% and %LOCALAPPDATA% on Windows, ~/Library/Application Support and ~/Library/Caches on macOS, and the defaults in the table everywhere else.

Checking where things are

The --print-directories option prints the five directories j has resolved and then carries on starting up: 

    $ j --print-directories
    config   /home/you/.config/j
    data     /home/you/.local/share/j
    state    /home/you/.local/state/j
    cache    /home/you/.cache/j
    runtime  /run/user/1000/j

If j is still using a ~/.j directory it says so, and lists where migrating would put each file instead. Printing does not create anything.

If you already have a ~/.j

Nothing changes. If j finds a ~/.j directory it uses it for everything, exactly as it always did, and never writes anywhere else. Upgrading j will not move your mail or your preferences.

When you want the new layout, start j once with the --migrate-to-xdg option: 

    j --migrate-to-xdg

j moves each file to its new home, discards the few that are recreated on every run anyway (the port, swank and log files), and then starts up on the new layout. Nothing is overwritten: if a file already exists at its destination, the copy in ~/.j is left where it is. Anything j does not recognize — and anything that could not be moved — stays in ~/.j, which is renamed to ~/.j.migrated so that j does not mistake it for a layout to go back to. j prints what it did, so read the output before deleting anything.

Putting everything somewhere else

The --home option still overrides all of this. Given --home=directory, j ignores the $XDG_* variables and uses directory/.config/j, directory/.local/share/j, directory/.local/state/j and directory/.cache/j. This is the way to run two independent copies of j, or to keep j's files on a removable disk.
