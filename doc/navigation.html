Getting Around

The ways to move between files, buffers and windows, and within a file, with their default key mappings. Any of them can be remapped; see Key Mappings. In vim edit mode, see also Vim keys.

The finders below share their keys. In any of them, the key of another, such as Ctrl T in the middle of a Ctrl P search, switches to it with what you have typed; Ctrl Shift P there switches back. Up and Down move through the list, or through the history when there is no list, and Alt Down lists the history.

Files

  • Ctrl P (findFileInProject) finds a file in the current project, its open buffers or its recent files. Type a few characters of the name, in order, such as ofth for OpenFileTextFieldHandler.java; words separated by spaces match in any order. Enter opens the selected file, Ctrl Enter opens it in the other window, and name:N goes to line N. Ctrl Shift P switches to finding a command, and back, keeping what you typed.
  • Ctrl O (openFile) finds a file under the current buffer's directory, the same way, and in the project if nothing there matches. A path lists that directory: Tab fills in the selected entry and Enter goes into a directory. A URL, or Shift Enter, opens exactly what you typed. openFileInOtherWindow and Ctrl Shift O (openFileInOtherFrame) open in another window or frame.
  • Alt R (recentFiles) finds a file you have visited recently, the most recent first.
  • Ctrl Shift G (gotoFile) opens the file named at the caret.
  • Ctrl D (dir) opens a directory buffer; dirProjectDir opens the project root in one.

Commands and help

  • F1 (help) finds a help topic: a page of this manual, a command or a preference.
  • Ctrl Shift P (findAction) finds a command by its name or description, shows its key binding, and runs it. Commands recently run by name, from here or Alt X, are listed first.
  • Alt X (executeCommand) runs a command by name, with an argument if it takes one.
  • apropos lists the commands and preferences whose names contain a pattern.

Buffers and windows

  • Ctrl E (switchBuffer) finds an open buffer and switches to it; with nothing typed, Enter goes back to the buffer before.
  • Alt Left and Alt Right (prevBuffer, nextBuffer) cycle through the open buffers.
  • Alt B (sidebarListBuffers) moves to the buffer list in the sidebar, and Alt = (toggleSidebar) shows or hides the sidebar.
  • F10 and Ctrl F10 (splitWindow, vsplitWindow) split the window; Alt O (nextWindow) moves to the next one.

Within a file

  • Ctrl J (jumpToLine) goes to a line.
  • Ctrl F, F6 and Ctrl L (find, findInFiles, listOccurrences) search the buffer, a set of files, and list every match.
  • Ctrl T (findTag) finds a definition, fuzzily, among the buffer's tags and its tag files; in any mode with tags, Markdown's headings among them. Alt . (findTagAtDot) goes to the definition of the name at the caret in Java, C, C++, PHP, Perl and Lisp modes; Ctrl Shift T (sidebarListTags) moves to the list of the buffer's tags in the sidebar.
  • Alt 0 to Alt 9 drop a bookmark and Ctrl 0 to Ctrl 9 return to it (dropBookmark, gotoBookmark). Ctrl ` (findBookmark) lists them all, with their lines, to pick from.
  • jumps (Go > Jumps...) and changeList (File > Changes...) list the jump list and where the buffer was changed, the current position marked.
  • Ctrl Alt N and Ctrl Alt P (nextChange, previousChange) move between the changes you have made.

Vim keys

In vim edit mode, outside insert mode, vim's key map is asked first. It takes every plain character and a few chords: Ctrl O and Ctrl I (the jump list), Ctrl F and Ctrl B (paging), Ctrl ^, Ctrl R, Ctrl V, Ctrl A and Ctrl X. So Ctrl O doesn't open the location bar and Ctrl F doesn't find; every other key above, Ctrl P and Ctrl Shift P among them, works as it does without vim. Any of j's commands also runs as an ex command, as in :findFileInProject or :openFile. As you type a name after :, a list shows the ex commands and j commands that match it: Tab fills one in, and Enter runs the line, or the command you moved the selection to. The findAction list shows a command's vim keys before j's.

Vim's own keys for getting around:

  • :N, NG, gg, G: go to a line, the first, the last.
  • /, ?, n, N, *, #: search forward, back, again, for the word at the caret.
  • %: the matching bracket.
  • H, M, L: the top, middle and bottom of the window.
  • zz, zt, zb: scroll the caret's line to the center, top or bottom.
  • <C-f>, <C-b>: page down, up.
  • }, {, ]], [[: paragraphs, sections.
  • mx, `x, 'x: set a mark, go to it; A to Z are file marks, shared with dropBookmark.
  • <C-o>, <C-i>: back and forward through the jump list.
  • <C-^>: the alternate buffer.
  • gx: follow a link.
  • gd: go to the definition of the name at the caret.
  • g;, g,: back and forward through the buffer's changes; :changes and :jumps list them, and the jump list.
  • <C-w>s, <C-w>v, :sp file, :vs file: split the window, or side by side.
  • <C-w>h, j, k, l: the window left, down, up, right.
  • <C-w>w, <C-w>W, <C-w>p: the next, previous, prior window.
  • <C-w>c, <C-w>o, :clo, :on: close the window, the others.

Projects

A buffer's project is the directory findFileInProject and dirProjectDir work from. It is the first of:

  1. the projectRoot preference, an absolute path;
  2. the outermost directory above the buffer's file that holds a .j-project directory, which groups several repositories into one project;
  3. the nearest directory above it that is a git or Subversion root;
  4. the buffer's own directory, if it is under your home directory.

The search stops below your home directory, which is never a project.

The project's files are listed in the background the first time you press Ctrl P, and kept: later, the list is shown at once and rescanned in the background when it is older than finderRescanSeconds. rescanProject rescans it now. Files you save in j are added as you save them.

The list leaves out what .gitignore files, .git/info/exclude and ~/.config/git/ignore ignore (except that ! patterns are not supported), the directories .git, .hg, .svn, node_modules, build, target, dist, out, .gradle, .idea, .cpcache, .clj-kondo, __pycache__ and .venv, names matching filenameCompletionsExcludePattern, and git worktrees nested in the project. It stops at finderMaxFiles.
