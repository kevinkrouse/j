Markdown Mode

Markdown mode is used for files whose names end in .md, .markdown or .mkd. You can change that with the MarkdownMode.files property, as described in Modes.

Highlighting

Markdown mode colors CommonMark, with GitHub's tables, task lists and strikethrough: headings, emphasis, inline code, fenced and indented code blocks, links and images, block quotes, lists, rules, tables, HTML comments and tags, and front matter.

A fence that names its language, such as ```java, ```py or ```sh, has its code colored the way that language's own mode colors it. The language is the first word after the backticks; the usual names and abbreviations are recognized, as are the names of j's modes. A fence that names no language, or one j has no mode for, is colored as plain code.

Code blocks and inline code are drawn on a shaded background, a code block from edge to edge of the window. Code in a code block is in italic, as the theme's codeBlock style is by default; to turn that off, add this line to your preferences file: 

    MarkdownMode.style.codeBlock = plain

Hidden markup

Markdown's markup is hidden until the caret is in what it marks. A link shows only its text; bold, italic and struck-through text and inline code show without their asterisks, underscores, tildes and backticks; and a code block shows its code without its fence lines. A block quote's > is drawn as a thin vertical bar in its place, so the text of the quote doesn't move.

When the caret is in a link, an emphasis or a span of code, its markup is shown again, so you can edit it; the rest of the line stays as it was. With the caret anywhere in a code block, both of its fence lines are shown.

The conceal property says what to hide, as a list. markup, the default, hides the markup described above; headings hides the # of headings and the underlines of setext headings as well; none hides nothing: 

    MarkdownMode.conceal = markup, headings

Tasks

A task is a list item that begins with a box. The box shows the task's state, and each state has its own color: 

    - [ ] not started
    - [/] in progress
    - [x] done
    - [-] cancelled

task moves the tasks on the caret's line, or on every line of the selection, from one state to the next: not started, in progress, done, and around again. A list item without a box gets one, and a line of text becomes a task. With an argument, task sets a state instead: task done, task doing, task todo. task cancel cancels the tasks, or, if they are all cancelled already, starts them again. Lines inside code blocks are left alone.

task is mapped to Alt Enter and Alt C, and task cancel to Ctrl Shift Enter. Ctrl Enter is followLinkOrTask: on a link it follows the link, and otherwise it does what task does on a list item. On a line of text, Ctrl Enter does nothing.

Links

followLink goes where the link at the caret points. A link can be written [text](target), ![alt](image), [text][label] with a [label]: target line elsewhere in the file, <https://example.com>, or just a URL. A target can be:

  • #heading, a heading in the same file, named as GitHub names it: the heading in lower case, without punctuation, with its spaces as hyphens (# Hello, World! is #hello-world);
  • a file, relative to the directory of the file you're editing or absolute, optionally followed by #heading, or by #L42 for line 42;
  • a URL, which is opened in the browser.

Ctrl-clicking a link follows it. If you hold down Ctrl with the mouse over a link, the link is drawn underlined, as clicking would follow it, and the mouse pointer changes to a hand. In vim edit mode, gx follows the link at the caret.

Following a link is a jump, so jumpBack (Ctrl O in vim edit mode) takes you back.

Headings

The bottom pane of the sidebar shows the file's headings as an outline, each heading under the one it belongs to. The selection follows the caret as you move around the file, and clicking a heading, or pressing Enter on it, moves the caret to it. The status bar shows the headings down to the one the caret is under, for example Install › From Source.

Folding

fold folds what the caret is in: the code of a code block, the lines indented under a list item, or the section under a heading, down to the next heading of the same or a higher level. If that is folded already, the one around it is folded instead, so folding again and again folds further out. foldHeadings folds everything but the headings, leaving an outline of the file; with a level, such as foldHeadings 2, it leaves only the headings down to that level.

In vim edit mode, za, zc, zo, zR and zM fold and unfold as they do in vim; zM is foldHeadings.

Themes

Markdown mode's styles are built on the shared styles, so a theme that sets color.heading, color.link or color.todo sets them in Markdown mode too. To change one in Markdown mode only, prefix it with MarkdownMode.: 

    MarkdownMode.color.heading1 = #cf222e
    MarkdownMode.style.heading1 = bold

The shaded background of code is a shade of the theme's background, made not to be mistaken for the current line's highlight. To choose it yourself, set color.codeBackground.

listStyles in a Markdown buffer shows every style Markdown mode uses, each drawn in itself, with what it takes its color and style from.

The following commands are specifically relevant in Markdown mode:

  • foldAll
  • foldHeadings
  • followLink
  • followLinkOrTask
