Edit Modes

J has two ways of reading the keyboard. In the default simple edit mode every key means itself: a printable character that no key map claims is inserted into the buffer. In vim edit mode the keyboard is modal, as it is in vi and its descendants: a key means one thing while you are typing text and another while you are giving commands.

Note that "edit mode" and mode are different things. A buffer's mode is the language it holds -- Java mode, HTML mode. Its edit mode is how the keyboard behaves.

Turning it on

Add this to your preferences file: 

    editMode=vim

Like any other preference it can be set for one mode only: 

    JavaMode.editMode=vim

Only ordinary text buffers are affected. Directory buffers, image buffers and the like bind plain letters as commands of their own and are always in simple edit mode.

What is there

Normal, insert, replace, visual, visual-line and visual-block modes, operator-pending commands, counts, registers, marks and the dot command:
motions h j k l 0 ^ $ w W b B e E ge gE gg G | f F t T ; , { } ( ) ]] [[ ][ [] % [( ]) [{ ]} H M L and the arrow keys
operators d c y > < gu gU g~, doubled for whole lines (dd, cc, yy)
changes x X D C s S r J gJ ~ p P, and Ctrl A / Ctrl X, which add the count to the number at or after the caret or take it away: decimal with a leading minus, 0x hexadecimal and 0b binary, as nvim's default nrformats has them, keeping the width of 007 or 0x0f.
insert i I a A o O, leaving with Escape; while typing, Ctrl T and Ctrl D add or take away one indent, rounded to a multiple of it. o and O indent the new line by the language in a mode j can indent, as nvim does with filetype indent, and like the line they start from elsewhere, as vim's autoindent does; cc and S keep the line's indent. Escape takes such an indent away again if nothing was typed after it. Ctrl W deletes the word before the caret and Ctrl U the line before it but its indent, both stopping once where typing began and joining lines at the start of one; in replace mode they put back what was typed over. Ctrl R and a register name types the register's text, and . types the same text again. Ctrl O runs one normal-mode command, shown as -- (insert) --, and comes back. An arrow key or Ctrl O splits the insert, as in vim: u undoes each side separately, and . repeats only what was typed after it.
replace R, which types over what is already there until Escape. Backspace walks the session backwards, putting back each character it typed over — until the caret moves by something other than typing, after which, as in vim, it only steps left.
text objects iw aw iW aW, the quote pairs i" a" i' a' and the backtick pair, i( a( i[ a[ i{ a{ i< a< with the b and B aliases, and ip ap
search / ? n N * # g* g#. Every match of the last pattern is highlighted, as nvim's hlsearch does by default, until :noh or the next search; :set nohls turns it off. As the pattern is typed the caret goes to where it would find (incsearch), the match it is on picked out in a color of its own; Ctrl G and Ctrl T step to the next match and the one before, Enter searches, Escape puts the caret back. The colors are color.searchMatchBackground and color.currentSearchMatchBackground. The last pattern is every window's, as in vim, unless shareSearch is false, and it is j's own last search too: j's findNext (F3) goes on with a /, and n with a find made in simple mode. :noh is j's clearSearchHighlight.
scroll zz zt zb, which are j's own toCenter, toTop and toBottom; Ctrl F and Ctrl B, which are its pageDown and pageUp with the vim argument
folds za zc zo zR zM, which are j's own toggleFold, fold, unfoldHere, unfoldAll and foldAll. The mode says what a fold takes in.
links gx, j's followLink: the URL, Markdown link or #heading at the caret
buffers Ctrl ^ (or Ctrl 6), the alternate file: the buffer used most recently before this one
windows Ctrl W then s or v to split, h j k l (or the arrows) to the window beside, of several the one level with the caret, w and W to the next and the one before (with a count, to that window), p to the one used last, c and q to close, o to close the others, and = to make them the same size again; :sp and :vs, with a file or without, :q, :clo and :on. A split shows the same buffer twice, with the caret in the top or left window, as in vim; a window closing gives its space and the caret to the next one. Each split and close makes the windows the same size again, as vim's equalalways does, even after a divider was dragged.
ex : with ranges (%, 1,5, ., $, 'a, /pat/ and offsets), then :d :y :s :j :m :t :sort :g :v :normal :delmarks :w :wq :set :noh, @: to run the last one again, and any command j already knows. : in visual mode fills in '<,'>.
visual v V Ctrl V o O gv, any operator over the selection, and J gJ p P r u U ~, and Ctrl A / Ctrl X on the first number of each line, which g Ctrl A / g Ctrl X make a sequence. D C S R X Y take whole lines, as in vim, even from a characterwise selection. p leaves what it replaced in the unnamed register; P leaves the registers alone.

Over a block (Ctrl V, $ to take each line to its end, O to the other side), d x y c s r u U ~ < > J p P work on the block itself, as do X Y; D C take it to the end of each line. I and A insert before and after it, and what is typed on the first line goes onto the others at Escape: I skips a line that ends before the block, A pads it out with spaces. A tab the block's edge cuts through becomes spaces. A blockwise register p puts as a block, padding short lines and adding lines at the end of the buffer as it needs.

registers "a through "z (upper case appends), which are j's own registers and so kept from one session to the next; the unnamed register and "1-"9, which are j's kill ring, newest first, so that a yank is what j's paste pastes and a copy in j or another program is what p puts; "+, the system clipboard, and "*, the primary selection; and "0, "-, "_
marks m, `, ', ]`, [`, ]', [', `< / `> after a selection, `. (the last change), `[ and `] (what it or the last yank covered), `^ (where insert stopped), and `` / '' (before the last jump). The file marks, A to Z, are j's bookmarks, and `A goes into the file one is in. The jump list is j's: Ctrl O back, Ctrl I or Tab forward, into other files too, over vim's jumps and j's own (jumpBack).
other u, Ctrl R, .

Counts work where vim's do, and multiply across an operator and its motion: 2d3w deletes six words, and 3iab<Esc> types ab three times, as 3o opens three lines. An insert session is one undo step, so u after cwsomething<Esc> puts back both what went and what came.

What is not there yet

Macros (q, and the rest of @), the rest of the insert-mode commands (completion, Ctrl V, Ctrl R Ctrl O and Ctrl R Ctrl P, and the like), the it, is and as text objects.

Of the ex commands: :marks as a listing, the c flag on :s, which is reported rather than silently replacing everything, a :s pattern matching \n to join lines, and in a replacement ~ (the previous replacement) and the case changes \u \U \l \L \e \E.

Outside insert mode a plain character never inserts itself, bound or not. A chord or function key that vim mode does not claim falls through to j's own key maps, so Ctrl S still saves and Alt X still prompts for a command. Ctrl W is vim's window prefix, and never reaches j's killBuffer. In insert mode keys go to j's key maps as they do in simple mode, apart from Escape and the few vim mode binds there (Ctrl T, Ctrl D, Ctrl W, Ctrl U, Ctrl R, Ctrl O).

Changing the bindings

The bindings are not built into j: they are read from a table, and you can replace it or override parts of it.

The table

The built-in table ships as default-keymap.conf inside j. Each row is a binding: 

    # modes  keys            kind      command           args
    n,v,o    w               motion    moveByWords       forward
    n,v,o    f<character>    motion    moveToCharacter   forward,inclusive
    n,o,v    d               operator  delete            -
    n        i               action    enterInsertMode   at=here,isEdit
    n        x               keytokey  dl

modes are the letters vim's map commands use: n normal, v visual, o operator-pending, i insert. keys is the key sequence in vim's notation; <character> stands for any one key, which is how f waits for the character to find. kind is one of motion, operator, action, textobj, search, ex, keytokey (the key stands for the keys in the command column, as x stands for dl), command (one of j's own commands, by name) or idle (the key does nothing). args are comma separated, either name=value or a bare name meaning true, or - for none.

To replace the whole table, copy it and set: 

    vimKeyMap=/home/you/.config/j/vim-keymap.conf

Your vimrc

To change a few bindings rather than all of them, put them in ~/.config/j/vimrc in the form you already know: 

    " j reads the parts of a vimrc it understands and ignores the rest.
    let mapleader = ","
    set shiftwidth=4

    nnoremap Y y$
    vnoremap < <gv
    nnoremap <leader>w :save<CR>

map, nmap, vmap, xmap, omap, imap and cmap (keys at the / prompt) are understood, with their noremap and unmap forms (a noremap's keys mean what they do built in, a map's may be mappings too), along with set and let mapleader. A right-hand side that begins with : and ends with <CR> runs one of j's own commands, which is how a key reaches something the modal layer knows nothing about; a name j has no command for (:w, :q) is run as the vim ex command it is.

Anything else in the file -- vimscript, plugins, autocommands -- is reported in the log and skipped, so an existing vimrc can be pointed at j without being cut down first.

When a key is both a command and the start of a longer mapping, the longer one wins if you type it; otherwise the shorter one runs as soon as the next key shows it was not coming. Nothing is decided on a timer.

Where it differs from vim

These are known and deliberate:

  • > and < shift by j's indentSize unless a vimrc sets shiftwidth, and the indent they produce follows j's useTabs.
  • The numbered registers are j's kill ring, which every yank and delete goes into, small ones too: after x or yy, "1 holds what it took, where vim keeps "1 for deletes of a line or more. Every yank and delete goes to the system clipboard, as a copy in j does, as vim does with clipboard=unnamedplus. A register j keeps as a file, or a copy from another program, comes back as lines when it ends in a newline; one vim took this session comes back as it was taken.
  • { } ( ) ]] [[ find paragraphs and sections by vim's default paragraphs and sections (the nroff macros, such as .PP and .SH); the two cannot be :set.
  • % and [( ]) [{ ]} skip brackets in quotes line by line: a string continued onto the next line by a backslash at the end of one is not seen as a string, where vim skips the brackets in it.
  • Marks a to z are per editor rather than per buffer. A mark on a line J joins to the one above is lost; vim moves it with the text.
  • G, gg, dd, :N, Ctrl D and the like go to the first non-blank of the line, as vim does by default; nvim keeps the caret's column there (nostartofline).
  • d2w and the like over several lines stop at the end of the first: on a, b, c on lines of their own, nvim deletes to the end of the second.
  • . after a visual command repeats it over as much again from the caret: as many lines, or characters, or a block as many lines down and characters across. A characterwise selection over more than one line is the exception: its . is at the caret alone, where vim takes in as many lines again. A block's width is counted in characters, where vim counts screen columns, so a block over tabs repeats narrower.
  • > and < over a block leave the blanks at its left edge as spaces, where vim uses tabs when expandtab is off.
  • A tab a block's edge cuts through is painted whole; vim paints only the columns inside the block. And A over a block whose right edge cuts a tab on its first line appends there, before the tab, and at the same column on the other lines. vim appends after the tab on the first line, and puts a tab before the text on the others.
  • Ctrl R (redo) leaves the caret where the edit left it; vim puts it back where the command was typed. The two agree for most commands, but not after Ctrl A or p.
  • There is one jump list and one set of file marks for all of j, where vim keeps a jump list for each window. A file mark on a deleted line moves to the line after, as j's bookmarks do; vim forgets it. And u leaves `[ and `] where they were, where vim moves them to what it restored. After J, `. is where the join was, and after :m the first line moved; vim puts it on the next line and where the lines came from.
  • :g runs its command on the matching lines from the bottom up, where vim goes from the top. Commands that treat each line alone (:d, :s, :normal) come out the same, but :g/^/m0 does not reverse the buffer, and the caret ends on the first matching line rather than the last.
  • vmap and xmap are the same thing, one visual mode for every kind of selection.
  • Patterns are vim's, in /, ?, :s, :g and :sort alike: the four magic levels (\v \m \M \V, with \m the default, so /a\+ is one or more and /a+ is the characters), groups and backreferences, \{n,m} and its non-greedy \{-}, \zs and \ze, the \@= family, the letter classes, POSIX classes in brackets, \%x.. and friends, ~, and \c / \C. ignorecase and smartcase work, and searching is case sensitive by default as in vim. What is refused, by name, rather than quietly misread: \%V and the other window- and cursor-dependent atoms, \&, \zs or \ze inside a group or beside a top-level \|, and a \zs after anything of variable width — including the common .*\zsfoo. Vim's \zs lands after the greedy match, so that pattern means the last foo on the line; the construct it is translated into lands at the leftmost place instead, which would mean every foo. It is refused until it can be done properly. A \zs after something of fixed width, such as foo\zsbar, works. \k, \i and \f use vim's usual character sets rather than reading iskeyword. j's own sortLines takes Java's syntax, as the rest of j does.
  • The pattern for / is typed at the top of the editor, in the location bar, rather than at the bottom. Escape abandons the search, and an operator waiting on it — the d of d/foo — is abandoned with it.
  • After a bad pattern, j's findNext finds nothing, as n reports the pattern bad again. A find made in simple mode is spelled for vim, for :s// and messages, as \V and the text when it is literal and \v and the Java regular expression when it is not, which is not always the same thing.
  • With a count, Ctrl G and Ctrl T at the / prompt step one match, and Enter stops on the one shown; nvim applies the count again from there.
  • smartcase is on by default, where vim and nvim have it off; as in both, it only matters once ignorecase is set. After a search the match under the caret is not given a color of its own, as nvim's CurSearch gives it; only while the pattern is typed. Search offsets (/foo/e) are not understood.
  • aw on a blank line does nothing, where vim counts the empty line as a word and takes the next one with it.
  • Enter in insert mode is whatever j binds it to in the buffer's mode: newlineAndIndent in the programming modes, which indents by the language rather than copying the line above as vim's autoindent does, and a plain newline in plain text, which does not indent. An indent nothing was typed after goes again at Escape or the next Enter, as in vim.
  • The arrow keys in insert mode are j's, and differ from vim's at the edges: Right at the end of a line wraps to the next one, and Up on the first line can move the caret along it, where vim's do not move.
  • Ctrl R reads the registers p can put; the read-only ones (. : / %) and = are not there. Ctrl R Ctrl R is the same as Ctrl R, since control characters are always typed as they are. Ctrl O followed by a command that switches buffers leaves insert mode behind, where vim goes on inserting in the new one.
  • A character outside the Basic Multilingual Plane, such as an emoji, is one character to motions and edits, as in vim. But | and j/k count columns in UTF-16 units where vim counts screen cells. The two agree for an emoji, which is two of each, and differ past a wide character such as 中 (one unit, two cells) or a narrow one outside the plane such as 𝐀 (two units, one cell).
  • zt leaves one line of context above the caret, because it is j's toTop; vim leaves none unless 'scrolloff' is set. The command was left as j has it rather than changed to suit this mode.
  • :normal! runs its keys through your mappings, as :normal does; vim's leaves them out. Your mappings share one table with the built-in bindings, so there is no unmapped table to run them through instead.
  • A backwards range such as :5,1d is put the right way round and run, where vim asks first (E493). :sort l is accepted, and sorts by code point, which is what the C locale gives.
  • :w is j's save: an unmodified buffer is not rewritten ("Not modified"), and a buffer with no name opens the Save As dialog where vim says E32. :wq closes the window, and when it is the last one leaves j, which asks first if other buffers have unsaved changes where vim refuses with E37. :w FILE and :w! FILE work; writing part of a buffer (:1,5w) and writing to a command (:w !cmd) do not.
  • Ctrl ^ takes no count: j's buffers have no numbers to give it.
  • A window left in visual mode keeps its selection, and the one Ctrl W goes to is in normal mode; vim carries visual mode into it. A count before Ctrl W s or v is not a size. :q! is :q: on the last window j asks before leaving if buffers have unsaved changes. The other Ctrl W commands (n x r R T + - < > _ |) are not there.
