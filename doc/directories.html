Directory Buffers

Directory buffers let you browse for files and perform basic file management functions.

You can open a directory buffer by specifying the name of the directory in the Open File dialog or on the command line when starting j. The command dir, mapped by default to Ctrl D, opens a directory buffer on the current directory.

The command dirHomeDir, available on the tool bar, opens a directory buffer on your home directory.

A dimmed hint over the listing shows the keys to open a file, go up, and see the rest, the ones for the edit mode you are in. It scrolls away with the listing.

The popup

? opens a popup of the directory's keys (modePopup):
  • Filters, each after -, as the git log's: -s steps the sort through name, date and size (s too); -p types a pattern the listing is limited to, as dirLimit does (empty for all); -. shows or hides the hidden names (. too); x clears them all, and the reverse.
  • View, after - too: r reverses the sort, keeping . and .. on top; d lists directories over the files, whatever the sort (dirSortDirectoriesFirst to start with); h writes sizes as ls -h does, 4.0K and 12M (dirHumanReadableSizes); t steps the time style through locale (Oct 16 09:02), iso (10-16 09:02), long-iso (2026-10-16 09:02) and age, how long ago (5m, 3h, 4mo), as the git log writes it (dirTimeStyle).
  • Go: open, Backspace up (u too in simple edit mode; in vim edit mode - is the options'), back, forward and home. Shift Enter opens the file or directory at the caret in a new window over the listing, Ctrl Enter in one beside it.
  • Files: a opens a new file, written when it is saved (the directories it is in made if need be), A makes a new directory; pick, copy, move, delete, a shell command, and rescan.

;, Insert or t picks the file at the caret, or each file a selection covers, and again unpicks it; a box in a column at the left shows what is picked, a click on one toggles it, and a Shift click sets the files from the last one clicked to it the same way. Copy, move, delete and the shell command take the files a selection covers, else those picked, else the file at the caret; in vim, so do a visual selection's ;, D, C, R and !. A selection with no file in it takes nothing. Once done, they unpick the picked files they took; the rest stay picked. Ctrl ; unpicks every file, as in the git status. Picks belong to this directory listing and are separate from Git picks. Rescanning keeps picks for files still present. To copy only one of several picked files, select that file first; the selection takes precedence. Its keys are the listing's own in the edit mode in use, so each works with the popup closed too.

Where the View options work. j lists a directory itself, or, with dirUseNativeFormat (the default on Unix), runs ls. Reverse and directories first are j's in either, so they work everywhere, a remote listing too. In j's own listing, sizes and time styles are j's as well. With ls, human sizes are its -h, which GNU's, the BSDs' (macOS's) and busybox's take, and a time style is its --time-style, which only GNU's takes: elsewhere, as on macOS, ls writes dates its own way. An age is j's in every listing, written over the date ls or a server wrote: to the minute with GNU's ls, which j asks for a long-iso date; elsewhere a date over six months old has no time, so its age is to the day. A remote listing's sizes and other dates are as its server writes them.

The first column is colored by permission, read, write and execute (DirectoryMode.color.permissionRead, permissionWrite, permissionExecute and permissionNone for a -), then the size (DirectoryMode.color.size) and the date (DirectoryMode.color.date). j's own listing has the column too: the POSIX permissions, or on Windows the owner's read, write and execute. A filter changes the listing at once and leaves the popup open, so several can be set; a command closes it.

The filters are also chips in a bar over the listing, each after its key: sort by: name, limit to and show hidden. A chip is highlighted, with a × to clear it, when it is set. A click on the sort chip steps the sort, one on the limit chip types a pattern over it, as l (-p in vim edit mode) does (Up and Down step through the patterns used before), and one on the show hidden chip shows or hides the hidden names. x puts them all back as a listing starts, as it clears the git log's. The bar, the popup and the keys change the same values.

Hidden names are those starting with a dot, those matching filenameCompletionsExcludePattern, and, in a repository, those its version control (git, Subversion) ignores. They are left out unless dirShowHidden is true or show hidden is set; shown, they are muted, and the ignored ones italic too. What is in an ignored directory is ignored, as git and Subversion have it; but a listing of a directory its repository ignores, which they wouldn't list at all, hides nothing as ignored, so a home directory kept in a repository that ignores everything else still lists its directories' files.

Escape closes it, as does a click outside it. ? opens this help; Ctrl H then a key opens the help for that key.
