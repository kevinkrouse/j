Icons

j's icons are SVG and are rendered by java2d at drawn by org.armedbear.j.util.SvgIcon. The icons are resized by uiScale, and allow a theme to change what color the icons are drawn in.

Drawing them in j rather than with a rendering library keeps j free of dependencies, but it means only a small part of SVG is understood. The subset is listed below.

Where the icons live

One file per icon, in src/org/armedbear/j/images/svg, named after the icon. Code asks for them by that bare name through org.armedbear.j.util.Utilities.getIconFromFile — "buffer", not "buffer.png", since the artwork is vector and the renderer picks the size. The result is cached per name, size and color.

The application logo is a real bitmap and is loaded with Utilities.getRasterIcon instead.

Elements

<svg> — the root. Its viewBox sets the coordinate system, and any presentation attribute on it is inherited by everything inside.

<path> — a shape, described by d.

<circle> — cx, cy, r.

<g> — a group. Passes its attributes down; draws nothing itself.

Attributes

viewBox, width, height

fill, stroke — a #rgb or #rrggbb color, the keyword none, or currentColor

stroke-width, stroke-linecap (butt, round, square), stroke-linejoin (miter, round, bevel), stroke-dasharray

color — on the root, the value currentColor resolves to

d, cx, cy, r

Path commands

Straight lines and elliptical arcs. Upper case is absolute, lower case relative.

M m — move to. Further coordinate pairs after a move are treated as line-to.

L l — line to

H h — horizontal line to

V v — vertical line to

A a — elliptical arc

Z z — close the subpath

Note that numbers may run together the way SVG allows: 3.5.5 is two numbers, 3.5 and .5, because a second decimal point begins a new one.

Not supported

Anything not listed above, including: the curve commands (C, S, Q, T); transform; opacity; gradients and patterns; <text>; <rect>, <line>, <polygon> and the other shape elements; <use> and <defs>; clip paths, masks and filters; embedded images; CSS, whether in a style attribute or a <style> element.

A curve or a rectangle is easy enough to express with the commands that are supported, and doing so keeps every icon drawable by the same few hundred lines.

Color

Icons are drawn in one color, named once on the root element:

<svg ... color="#4A4E57" fill="none" stroke="currentColor">

Every shape then says currentColor rather than repeating the value. Setting the iconColor preference overrides it for the whole set, which is how a theme meant for a dark background recolors the icons without a second set of files.

Conventions

These are not enforced, but the icons are drawn to them and a new one will look out of place otherwise.

A 0 0 16 16 viewBox, with shapes aligned to that grid.

Strokes of width 1 centred on half coordinates — 3.5, not 3 — so a vertical or horizontal line covers a whole pixel rather than straddling two.

File glyphs occupy x 3–13, y 2–14; folder glyphs x 2–14, y 3–13. The two carry similar visual weight when they sit next to each other in a list.

Node glyphs for the structure tree — class, interface, method, field — sit in an 8 by 8 box at x 2–10, y 2–10, leaving both right hand corners free for badges.

Badges are full 16 by 16 canvases with the mark in one corner, composed over a base icon by Utilities.getBadgedIcon. Visibility (public, protected, private), locked and modified go bottom right; modifiers (static, abstract, final) go top right, from x 10.5.

Before each badge is drawn, a fattened silhouette of it is erased from what is already there, which leaves a gap between the badge and the drawing underneath. The erasing happens in a transparent image, so the gap shows whatever the icon is sitting on — a white row, a selected one, the editor background — rather than punching a hole. That is why a badge can overlap the outline of a file or folder, which has no spare corner to give it.

Adding an icon

Write the file, then run ant test. Every icon in the directory is parsed and drawn at several sizes, and an unsupported construct fails the build. An icon that parses but draws nothing fails too.
